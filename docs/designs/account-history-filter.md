# 계정과목에서 거래내역 조회

2026-11-14 · 사용자 요청: 계정과목 이름을 누르면 해당 계정으로 거래내역을 필터링한다.

- 계정관리(활성·보관), 대시보드 잔액·이번 달 지출, 통계 계정 구성, 거래내역 흐름에 실제 링크를 제공한다. 거래입력의 계정 선택·계정 순서 드래그는 기존 동작을 유지한다.
- 잔액·계정관리 링크는 0001-01-01~오늘의 실제 거래를, 통계 잔액은 조회 종료일까지의 누적 거래를 연다. 통계 수입·지출과 대시보드 이번 달 지출은 원래 기간을 전달한다. 거래내역 흐름 링크는 현재 기간·태그를 유지한다.
- `/transactions`의 적용 조건에 `account_id`와 `include_descendants=true|false`를 추가한다. 이름 변경에 영향받지 않는 ID를 사용한다. 그룹 링크는 현재 하위 계정을 포함하고, 직접 기록·직접 잔액 행은 해당 계정만 조회한다. 그룹 자체의 과거 직접 기록과 보관 후손도 포함한다.
- 거래내역에 계정 선택·하위 계정 포함 체크박스를 제공한다. 날짜·태그·계정은 초안으로 편집하고 조회/프리셋 적용 시 함께 반영한다. 계정 변경은 첫 페이지로 이동한다. 적용 계정과 범위를 명시하고 전체 계정으로 필터를 해제할 수 있다.
- `GET /api/transaction-history`에서 계정 조건을 날짜·태그와 교집합으로 적용한 뒤 건수·100건 페이지를 계산한다. recursive CTE로 후손 ID를 선택하고 posting의 거래 ID 집합으로 필터링한다. 여러 분개가 일치해도 거래는 한 번만 세며 거래의 모든 분개·태그를 반환한다. 계정 수나 페이지 크기에 따른 N+1 조회는 추가하지 않는다.
- 잘못된·중복 계정 조건은 422, 없는 계정은 404다. 오류를 전체 조회로 바꾸지 않는다. 계정 조건이 없으면 기존 API/URL 동작을 유지한다.
- 요청 취소·늦은 응답 무시·적용 조건으로 재시도·수정 복귀·scroll/focus 복원 키에 계정/하위 범위를 포함한다. 수정으로 계정 조건에서 빠지면 이를 안내하고 서버의 마지막 페이지 보정을 따른다.
- 실제 기장만 조회하며 시나리오 가정은 포함하지 않는다. 거래내역은 기존 전체 통화 범위를 유지하므로 원화 전용 통계·활성 계정만 표시한 대시보드 소계와 단순 합계가 같다고 보장하지 않는다. 기존 거래·계층·보관 상태를 변경하지 않는다.

## 검증

백엔드: 단일/그룹/다단계/보관/직접 기록, 분개 중복과 전체 거래 보존, 날짜·태그·페이지 교집합, 잘못된/없는 계정, 쿼리 수·읽기 전용을 확인한다.
화면: 링크별 기간/범위, 초안 적용/해제, URL/Back/재시도/응답 순서, 100건 페이지 이동과 계정 변경 후 수정 복귀·페이지 보정, 모바일·키보드·axe를 확인한다. 전체 backend/E2E/build를 실행한다.
