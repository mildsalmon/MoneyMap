## Affected Pages/Routes

- `/transactions/new`: 차변·대변 클릭 선택, 아이템 마지막 조합, 분할 입력, 저장과 실행취소.
- `/transactions`: 실제 저장된 postings와 삭제 결과 확인.
- `/accounts`: 계정 이름·경로·보관·그룹 변경 후 입력 화면의 처리 확인.
- `/rules`: 규칙 생성·실행·삭제 후 기억 대상이 바뀌지 않는지 확인.
- 신규 `GET /api/transaction-input/last-pair`, `GET /api/transaction-input/recent`: 상태별 응답과 제한 조회.
- 기존 거래 POST/DELETE, 전용 개시잔액 API: 새 메타데이터와 원자적 저장, 호환성.

## Edge Cases and failure recovery

| Path | Realistic failure | Test | User-visible recovery |
|---|---|---|---|
| Migration | Disk full or invalid legacy row during backfill | B06-B07 | Startup stops with error; verified backup available, original ledger preserved |
| Save metadata | Posting validation fails after parent insert | B08-B10 | Save error, draft intact, no new memory |
| Last pair | Latest record exists but account became a group | B03-B04, B15 | No old-pair fallback; select a current account |
| Query transport | Timeout/network failure or out-of-order response | F05, F08 | Inline manual-entry fallback; current choices preserved |
| Legacy confirmation | Item changes before click or response finishes | F04, F08 | Stale result cannot apply; current item remains authoritative |
| Split validation | A partially filled row would be silently excluded | F12 | Row error, zero POSTs, complete/delete the row |
| Save completion | User enters the next item before response | F09-F10 | New draft intact, submitted item identified |
| Undo | Delete fails or old lookup finishes after deletion | B12, F16 | Error visible; only successful delete invalidates committed memory |
| Debt fill | Response arrives after amount was manually corrected | F14 | Manual amount retained |
| Navigation | Input unmounts during a request | F17 | No old response changes a new form or moves focus |
| Picker | Search hides selected item or names collide | F06, F15 | Selected summary/path remains visible; no selection change |

## Critical Paths and execution rules

1. First manual entry → same item recall → change cash/card → save → reload → only last pair; verify real persisted postings and unchanged amount/date during recall.
2. Legacy confirmation → save → normal recall; automatic rule generation and later rule deletion never replace it.
3. Latest delete/undo → prior surviving pair, and invalid latest → unavailable with no older fallback.
4. Slow lookup/save → edit while pending → newer manual values and focus remain intact.
5. Partial split row → blocked save → correct row → exact balanced postings saved.
6. Memo → save → reload/history read → memo text retained in ledger; draft cleared only if unchanged. A delayed save must preserve the next memo.

Python fixtures create an independent temporary DB per test. Existing Playwright configuration uses one worker and a port-specific temporary DB shared by specs: prepare unique item/account names and explicit ledger state in every test; do not rely on test order or on all recent rows belonging to this case. Never point these tests at the personal ledger. Delay/release actual request responses deliberately; register the exact response wait before clicking Save, then inspect persisted state. Prior learning applied: `account-settings-e2e-await-save-before-api-read` (10/10, 2026-09-05).

Required implementation checks: `cd backend && uv run pytest`, `cd frontend && npm run e2e`, `cd frontend && npm run build`. New input tests run alongside existing regression suites. There are no LLM/prompt changes and no eval suite is needed.
