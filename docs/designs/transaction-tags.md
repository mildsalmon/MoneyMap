# 거래 태그 검색·선택 UI

2026-10-24 · `거래입력 태그 UI 재설계`(P2)와 중복되는 `거래 태그 선택 UI 개선`(P3)을 함께 구현한다. 2026-10-25에 v0.11.0.0 릴리스 후보로 검증했다. main 병합 상태는 PR에서 확인한다.

## 사용 흐름과 선택 근거

기존 화면은 태그 입력·추가 버튼, 기존 태그 전체 체크 목록, 선택 칩을 동시에 보여줬다. 현재 사용 데이터의 읽기 전용 집계는 태그 12종·태그가 있는 거래 600건·거래당 최대 2개다. 이름이나 거래 내용을 설계 자료에 복사하지 않고 집계만 확인했다.

| 후보 | 판단 |
|---|---|
| 전체 체크 목록 유지 | 작은 선택 수에 비해 목록이 항상 많은 공간을 차지한다. 검색이 없다. |
| native datalist | 가벼우나 기존 값 선택과 새 값 생성·이미 선택됨을 명확히 구분하기 어렵다. |
| 검색 combobox + 선택 칩 | 검색·선택·생성을 한 곳에서 수행하고, 선택한 소수의 값만 남긴다. 채택. |

이력 API는 태그 이름만 제공한다. 사용 빈도나 최근 사용 순서를 추측해 추천하지 않고 서버 목록 순서를 유지한다. WAI의 [editable combobox 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)을 참고해 입력에 포커스를 유지하고 `aria-activedescendant`로 후보를 가리킨다.

## 구현 계약

- 입력과 수정이 공유하는 `TransactionForm`에 같은 선택기를 사용한다. 새 API·DB·의존성을 추가하지 않는다.
- 입력을 클릭하거나 포커스하면 기존 미선택 태그를 표시하고, 입력 문자열의 부분 일치로 좁힌다. 동일 이름은 첫 결과로 올리고 최대 30개 후보를 표시한다. 더 많은 결과는 검색어를 좁히도록 안내한다.
- 기존 후보 클릭 또는 위/아래 화살표 후 Enter로 선택한다. 새 이름은 명시적인 `새 태그 추가` 후보 또는 입력 후 Enter/쉼표로 추가한다. 화살표로 고르지 않은 입력은 Enter에서 해당 문자열을 사용한다. 일치하는 기존 이름이 있으면 기존 표기를 재사용한다.
- 선택한 태그만 칩으로 표시한다. 칩의 제거 버튼은 키보드·터치로 접근 가능하며 제거 후 인접 칩 또는 입력으로 포커스를 돌린다.
- Escape·Tab·바깥 포커스 이동으로 후보만 닫는다. 검색 문자열이나 선택 태그를 임의로 바꾸지 않는다. 입력 Enter는 거래 저장으로 전파하지 않는다. IME 조합과 keyCode229는 선택·거래 저장을 실행하지 않는다.
- 기존 최대 20개·이름 50자 규칙을 화면에 드러낸다. 20개에서 마지막 제거 버튼으로 포커스를 옮기고, 하나를 제거하면 입력이 다시 가능하다. 51자 입력은 잘라내지 않고 수정할 수 있게 남긴다.
- 프런트 선택 키는 기존 공백 제거·소문자 비교에 NFC를 추가한다. 최종 원장 저장의 정규화·중복 판정은 기존 백엔드 계약을 유지한다. 선택한 값은 목록 조회와 독립적으로 유지해 오류·목록 갱신으로 사라지지 않는다.
- 거래 수정의 저장·결과 확인 잠금은 선택기에 적용한다. 새 거래 입력은 기존 정책대로 저장 대기 중 다음 초안을 작성할 수 있으며, 늦은 저장 결과는 revision이 달라진 태그를 지우지 않는다.

## 표현·접근성

기존 DESIGN.md의 Pretendard·미색·장부초록·4px 반경을 재사용한다. 추가 카드·그림자·장식·움직임은 없다. 후보 목록은 필드 아래 팝업이며 실제 listbox가 스크롤을 소유해 입력의 제어 대상과 스크롤 영역을 일치시킨다. 모바일 칩·목록 후보·토글은 최소 44px, 긴 이름은 줄바꿈한다. 선택/제거 결과를 live status로 알리고 고유 ID로 입력·목록·현재 후보를 연결한다.

## 검증

[태그 전용 테스트](../../frontend/e2e/transaction-tags.spec.ts)는 다중 선택·생성·실제 제출 payload, Escape/Tab/포커스 이동, 한글 IME/229, NFC·공백·영문 대소문자, 20개/50자 경계, 늦은 응답 뒤 새 초안 보존, 60개 이상 목록·모바일·axe를 확인한다. 기존 입력·수정 테스트도 새 선택기를 통해 검증한다. 최종 전체 실행 결과는 [검증 기록](../verification/transaction-tags.md)에 남긴다.
