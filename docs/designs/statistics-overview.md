# 통계 통합 개요

2026-10-25 · feature/statistics-overview · 승인: 사용자에게서 범위 판단·구현을 위임받음(“너가 판단해서 진행하고 나한테 결과와 의도를 알려줄래?”).

## 목적과 선택

대시보드의 이번 달 지출 목록을 넘어, 선택 기간의 수익·비용 흐름과 기간말 자산·부채·순자산을 한 화면에서 확인한다. 통합 개요를 선택했다. 최소 합계만 먼저 제공하는 안은 월별 흐름·구성을 설명하지 못하고, 계정·태그 탐색부터 하는 안은 전체 돈의 변화를 먼저 보여주기 어렵다. 기존 Ink & Ledger UI와 표 대체 경로를 사용한다.

## 첫 버전 계약

- 별도 `/statistics` 페이지와 `GET /api/statistics?start=YYYY-MM-DD&end=YYYY-MM-DD`. 실제 장부 scenario_id=1, posted=1, 모든 분개와 참조 계정이 KRW인 거래 전체만 집계한다. 한 분개라도 조건에 맞지 않으면 거래 전체를 제외하고 모든 합계에 같은 적격 거래 집합을 사용한다. 비원화 제외 거래가 있으면 종료일까지의 제외 거래 건수와 원화 전용 안내를 보여준다. 원장·계정·태그를 변경하거나 재분류하지 않는다.
- 기본 올해 1월 1일~오늘. 이번 달·지난달·올해·최근 12개월·직접 날짜, URL에 적용 조건을 저장한다. 초안 수정은 조회하지 않고 조회 버튼/Enter로 적용한다. 통계의 오늘·프리셋은 브라우저 시간대와 관계없이 서울 달력 날짜를 사용하고 서버도 서울 기준 오늘을 응답한다. API는 단일 start/end 필수, 시작≤종료, 최대 3660일, 미래 종료일 금지. 10년 상한은 무제한 조회와 과도한 월별 응답을 막는다.
- 상단 기간 수입·지출·수지(수입−지출), 기간 시작 전일/종료일 순자산과 변화, 기간말 자산·부채를 표시한다. 순자산 변화와 수지의 차이는 개시잔액 등을 포함한 자본 변동으로 별도 표시한다. 수지를 저축액·현금 흐름이라고 부르지 않는다.
- 월별 표/막대는 기간으로 잘린 각 월의 수입·지출·수지와 그 월 조회 종료일의 순자산. 거래 없는 달은 0 흐름과 직전 잔액 유지. 첫 달 시작 이전은 기간 합계에서 제외하고 잔액에는 포함한다.
- 수익·비용 계정별 기간 순액과 기간말 자산·부채 구성 표. 전체 수익·비용 계정 집계이며 투자손익도 포함한다고 명시한다. 생활비 분석으로 오인시키지 않는다. 이전 투자손실을 일반 생활비로 자동 분류하지 않는다. 구매와 판매를 자동 상계하거나 관계를 추정하지 않는다.
- 자산→자산 이체·카드 원금 납부는 수입/지출에 넣지 않는다. 개시잔액은 equity 자본 변동이며 수입이 아니다. 환불/수익 취소의 부호를 보존한다. 카드 구매는 비용 발생 때 집계하고 납부 때 다시 세지 않는다.
- 계정 표는 직접 기장 합계를 먼저 구하고, 그룹 소계는 하위 직접 값의 합이며 전체 합계를 다시 더하지 않는다. 현재 계정 경로·순서로 표시하고 보관 계정도 기간 기록/잔액에 포함한다. 과거 시점의 계층을 복원한다고 주장하지 않는다. 마이너스통장의 음수 잔액은 자산 그룹 소계에서 빼고 양수 부채 크기로 부채 구성에 표시한다. 원래 계정 경로는 문맥으로 남긴다. 양수로 회복하면 자산에 표시한다. 총 순자산과 일치시킨다.
- 요청 한 번의 SQLite 읽기 snapshot에서 집계한다. 거래 전체를 브라우저로 내려받지 않고 고정된 수의 집계 SQL로 계정별 기간 합계·월별 흐름·월별 순자산 delta·시작 잔액·종료 잔액·비원화 제외 건수를 읽는다. 새 스키마/의존성 없음.
- 읽는 동안 이전 조건의 결과는 숨긴다. 오류는 빈 원장과 구분하고 적용 조건으로 재시도한다. 빠른 조건 변경/이탈 시 이전 요청은 취소되어 늦은 결과가 현재 화면을 덮지 않는다. gen 변경 시 재조회한다. 통계 화면은 읽기 전용이다.

## 검증과 구현 순서

1. 서버 집계와 API: 수입/환불/투자비용/카드 구매·납부/이체/개시잔액/보관 계정/그룹 직접 기장 이력/마이너스통장/비원화/빈 기간/월말·윤년/부분 월/입력 오류/고정 쿼리 수를 손계산 golden으로 검증.
2. 프런트: URL 조건/명시 적용/프리셋/월별 추이와 정확한 표/계정 그룹 구성/재시도/응답 순서/모바일 가로 넘침/키보드·axe를 검증.
3. 전체 backend·E2E·빌드와 코드·디자인 리뷰 후 TODO와 검증 기록을 갱신한다. ship/main merge는 이 작업 결과를 확인한 다음 별도 단계로 남긴다.

## 후속 범위

태그별 중복 합계·계정별 거래 drill-down, 전기 대비 비교, 생활비/투자 성과를 나누는 명시적 분류 정책, 다중 통화 환산은 후속이다. 첫 버전의 전체 수익·비용 집계를 생활비 통계로 대체하지 않는다. 잔액 대사와 나머지 TODO는 이 작업 완료 후 순서대로 착수 조건을 평가한다.

## 집계 부호와 대사

수입 = −Σ수익 분개, 지출 = Σ비용 분개, 자본 변동 = −Σ자본 분개. 기간 순자산 변화 = 수입−지출+자본 변동, 순자산 = 자산−부채. 자본 변동은 equity 분개에서 직접 집계하며 미설명 차이를 자본 변동으로 숨기지 않는다. 비원화 계정에 KRW 분개를 참조한 거래 전체 제외, 기간 전 제외 거래 경고, 자산 그룹 마이너스통장이 0을 넘는 golden을 추가한다.

## 구현 정밀도와 리뷰 보완

모든 금액은 정수로 집계한다. API는 JavaScript 안전 정수 범위를 넘는 결과와 SQLite 중간 SUM 오버플로를 `statistics_amount_out_of_range` 오류로 반환한다. 큰 값이 나중에 상쇄되더라도 SQLite 중간 합이 넘으면 조회를 거절할 수 있다. 화면 그룹 소계는 bigint로 계산해 안전한 개별 금액의 합산 정밀도를 유지한다. 통계 날짜 검증과 월말 계산은 UTC 달력 연산을 사용하며 오늘의 기준만 서울이다. 브라우저 지역에서 존재하지 않았던 날짜도 서울 달력 날짜로 조회할 수 있다.

구현 리뷰는 백엔드·프런트 독립 문맥과 기존 설계 문맥의 적대적 검토로 진행했다. SQLite 중간 합 오버플로, Pacific/Apia의 건너뛴 날짜, 모바일 긴 그룹명에 대한 회귀 테스트를 추가했다. 외부 모델 리뷰는 수행하지 않았다.
