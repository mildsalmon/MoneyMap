## 범위와 선택

변경 전 최근 입력은 저장 ID 내림차순 5건으로 제한됐다. 동일한 대상(실제 장부의
posted user/legacy_unknown 거래), 순서, 계정 추천 동작을 유지하면서 5건씩 더 조회한다.
태그 재설계는 UI안 비교가 남아 있고 거래내역 조회는 별도 로컬 작업이 있으므로,
독립적으로 완료할 수 있는 이 항목을 선택했다.

OFFSET은 새 저장·삭제로 페이지 경계가 밀릴 수 있고, limit 증가 방식은 이미 본
행을 재전송한다. 기존 ID 정렬과 partial index를 사용하는 before_id 커서를 선택한다.
API 응답 배열·기본 limit=5·최대 limit=20은 호환 유지한다. before_id는 선택 값이며
1 이상 SQLite signed 64-bit 정수 범위로 검증한다. 커서 행이 삭제되어도 id < cursor로 조회된다.

## 동작

```text
진입/저장/실행취소 → 첫 6건 조회 → 5건 표시 + 다음 행 존재 여부
더보기 → 마지막 표시 ID보다 작은 6건 조회 → 최대 5건 추가
실패 → 기존 목록과 커서 유지 → 같은 페이지 재시도
저장/실행취소/이탈 → 이전 요청 취소 → 이전 응답 반영 금지
```

- 첫 페이지/추가 페이지의 끝은 한 건 미리 읽기로 판단한다.
- 동시 클릭은 ref로 잠그고 진행 중 버튼을 비활성화한다.
- 항목 클릭은 기존 아이템 선택과 계정 추천을 재사용한다. 금액·메모를 바꾸지 않는다.
- 저장/실행취소로 장부 세대가 바뀌면 첫 5건으로 초기화한다.
- 여러 탭의 변경을 실시간 동기화하거나 목록 전체 스냅샷을 보장하지 않는다.
  다른 탭에서 새로 저장한 거래는 다시 진입하거나 현재 화면 갱신 시 확인한다.
- 새로운 테이블·마이그레이션·의존성 없음. 읽기 요청만 추가한다.
