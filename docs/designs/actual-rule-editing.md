## 범위와 정책

월급·월세의 내역, 두 계정, 원화 금액, 월간/주간 일정, 시작일/종료일을 편집한다.
새 테이블이나 라이브러리를 추가하지 않는다. 할부 및 시나리오 전용 편집은 제외한다.

- 기존 규칙 ID, last_materialized, 이미 생성된 거래와 source_rule_id를 보존한다.
- 적용 구간은 기존 생성기와 동일하게 `[max(start_date, last_materialized+1), min(오늘, end_date)]`다.
  처리되지 않은 과거 날짜에도 새 조건이 적용될 수 있다. 저장 시 자동 생성하지 않는다.
  처리일을 되돌리거나 과거 거래를 일괄 수정하는 동작은 없다.
- actual 규칙을 live-additive로 상속하는 활성/보관 시나리오 및 기준 전망은 다음 조회부터 반영한다.
  legacy snapshot은 기존 사본을 유지한다.
- 월간/주간과 날짜를 원본 그대로 채운다. 종료일 빈값은 null이다. 월간 31일은 기존 말일 당김을 따른다.
- KRW만 수정한다. 지원하지 않는 통화의 기존 규칙을 KRW로 바꾸지 않는다.

## 동시성 및 오류

```
GET rules → edit_token (규칙 전체 + 처리일 SHA256)
   → 초안 편집 → PUT + If-Match
      → BEGIN IMMEDIATE → 현재 토큰 비교 → 계정 검증 → UPDATE → COMMIT
                             └ 불일치: 409, 초안 보존
```

PUT는 If-Match가 없으면 428. 읽기 응답의 edit_token을 그대로 전달한다.
SQLite writer lock 안에서 비교 및 쓰기를 함께 수행한다. 생성기도 같은 writer lock을
사용하므로 편집과 자동 생성이 교차하여 오래된 내용/처리일을 저장하지 않는다.
토큰은 상태 비교이며 별도의 영구적인 버전 번호/수정 이력은 아니다.

실패한 요청은 자동 재전송하지 않는다. 4xx/명시적인 database_busy는 초안을 유지하고 재시도 가능.
네트워크/타임아웃/5xx/잘못된 성공 응답은 결과 불명으로 저장을 막는다.
최신 조회가 제출한 내용과 같으면 현재 내용의 반영을 확인한다. 다르면 서버 최신 내용과
초안을 비교하고 사용자가 최신 규칙을 기준으로 계속 수정하도록 한다. 다시 저장할 때에도
토큰을 재검증한다. 규칙 삭제는 초안을 보존하고 저장을 막는다.

저장/확인 중 폼과 취소·다른 규칙 작업을 잠근다. 초안이 있는 화면 이동/창 닫기를 경고한다.
모바일에서도 편집기는 표 스크롤 바깥의 반응형 그리드이고 기존 DESIGN 토큰을 쓴다.

## 테스트 계획

- HTTP: 처리일과 과거 거래 완전 보존, 누락/오래된 토큰, 동시 편집, 자동 생성 경합,
  소유권 교체, 잘못된 금액/계정/일정/기간, 원화 외 규칙 보호.
- 생성: 주간/월간, 시작/종료일, 윤년 말일, 미처리 과거와 다음 생성 금액.
- 전망: 기존 live active/archived 및 legacy snapshot 회귀 테스트 재사용.
- E2E: 원본 채움, 수정·취소, 중복 제출, 검증/503 후 재시도, 충돌 재확인,
  저장 응답 유실 후 현재 내용 확인, 최신 조회 실패, 삭제, 모바일, 화면 이동 보호.
- 전체 backend pytest, frontend E2E, production build.
