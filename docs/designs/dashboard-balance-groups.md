# 대시보드 잔액 그룹화

상태: 구현·리뷰·QA 완료, ship/main 반영 대기. `TODOS.md` P2 대시보드 잔액 분리 항목.

## 범위와 표시 규칙

- 기존 balances/account API를 사용한다. DB·회계 계산·월별 지출은 변경하지 않는다.
- 자산과 부채를 별도 표로 표시한다. `reporting_type`을 사용하므로 음수 마이너스통장은 부채 표에 나타난다. 부채의 원래 부호와 배지를 유지한다.
- 각 표에서 계정 트리의 최상위 그룹 및 저장된 순서를 사용한다. 루트의 일반 계정은 직접 표시한다. 하위 그룹은 경로를 표시해 동명 계정을 구분한다.
- 그룹 소계는 해당 표에 표시된 활성 계정의 **직접 잔액**을 한 번씩 더한다. API 잔액은 후손 합산값이 아니다. 그룹 자체의 과거 직접 잔액이 0이 아니면 `직접 잔액` 행으로 표시한다. 빈 그룹은 숨기지만 일반 계정의 0원 잔액은 표시한다.
- 마이너스통장이 있는 자산 그룹은 자산/부채 표에 나뉠 수 있다. 각 소계는 해당 표의 행만 포함한다.
- 보관 계정은 소계와 목록에서 제외한다. 전체 순자산은 보관 계정을 포함한 API 값을 유지하고 이를 명시한다.
- 계정 상태나 잔액 로딩/실패 중에는 0원 합계나 빈 목록 완료 상태로 오인하지 않도록 한다. 재시도는 기존 조회 훅을 사용한다.
- 기존 InkLedger 표 스타일, 중립적인 부채 색, 우측 정렬 숫자, 모바일 줄바꿈을 유지한다.

## 구조와 검토

```text
accounts ── accountTree (저장 순서) ─┐
balances (직접 잔액) ────────────────┤
                                   ├─ reporting_type별 표
                                   │   └─ 루트 그룹 → 경로/직접 잔액 → 소계
API net_worth ──────────────────────┴─ 전체 순자산 (보관 포함)
```

Architecture: 프론트엔드 표시 전용. 기존 트리 헬퍼와 조회 상태를 재사용한다. 새 엔드포인트·패키지·캐시는 필요 없다.
Code quality: 잔액 표를 별도 컴포넌트로 추출하고, 순수 변환 함수를 함께 둔다. 합계는 직접 잔액에서만 계산한다.
Tests: 기존 Playwright 테스트를 확장한다. 아래 신규 경로는 구현 시 함께 검증한다.
Performance: 추가 네트워크 요청 없음. 트리 정렬 후 각 계정을 한 번 방문하고 경로 길이만큼 표시 문자열을 만든다. 중첩 후손 조회를 반복하지 않는다.

## 테스트 계획

```text
대시보드 진입
  ├─ 기존: 활성/보관/복원, 0원, 미확인 계정 숨김
  ├─ 신규: 자산/부채 분리, 루트/중첩 경로, 저장 순서
  ├─ 신규: 그룹 직접 잔액, 보관 제외 소계, 이중 합산 방지
  ├─ 신규: 마이너스통장 분류와 0원 복귀
  ├─ 기존+확장: 계정 조회 지연/실패/재시도
  └─ 신규: 잔액 조회 지연/실패/재시도, 모바일 긴 경로
```

검증 명령: backend `uv run pytest`, frontend `npm run e2e`, `npm run build`. 브라우저 QA에서는 데스크톱과 모바일 표의 가독성 및 오류 복구를 확인한다.
