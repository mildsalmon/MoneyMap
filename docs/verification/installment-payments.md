# 무이자 할부 구현 검증

구현 검증: 2026-10-18. ship 최종 검증·문서 정리: 2026-10-24.
상태: v0.10.0.0 PR 준비 완료, main 반영 전. [설계 계약](../designs/installment-payments.md).

## 제공하는 흐름

1. 사이드바 `할부 관리`에서 `새 할부 구매`를 연다.
2. 구매 내역·구매일·비용/자산 계정·카드부채 계정·납부 통장·총액·개월 수·첫 납부일을 입력한다.
3. 회차 미리보기를 확인하고 구매 거래와 일정을 함께 저장한다.
4. 기존 거래 입력에서 실제 납부를 통장→카드로 기록한 뒤, 할부 화면에서 해당 거래를 검색해 회차에 배분한다. 구매 환불은 구매 계정→카드 거래를 연결한다.
5. 남은 원금·다음 납부일·완납 예정월을 확인한다. 날짜가 지난 미확인 회차는 거래 연결 또는 예정일 조정으로 해소한다.

합산 카드 납부 한 건을 여러 회차/구매에 배분할 수 있다. 중도상환도 실제 납부를 미래 회차에 연결한다. 연결은 원장 거래를 추가하지 않는다. 거래를 정정하려면 먼저 배분을 해제하며, 구매 거래 정정은 일정 연결도 해제한다. 일정 삭제는 구매 거래를 삭제하지 않는다.

현금 전망에는 기존 계정 설정에서 선택한 통장만 포함된다. 같은 카드의 반복 규칙이 있으면 포함 여부를 확인하기 전 별도 할부 전망을 보류한다. 규칙 포함 선택은 날짜·통장·카드·여러 할부의 합산 원금이 실제 규칙으로 충당될 때만 허용한다.

## 검증 결과

| 검증 | 결과 |
|---|---|
| `cd backend && uv run pytest -q` | 최종 560 passed |
| 전체 Playwright E2E | 최종 233 passed, 격리 포트 18769/15177 |
| 응답 지연 복구·일정 정정 포함 할부 집중 E2E | 6 passed, 별도 격리 포트 18768/15176 |
| `cd frontend && npm run build` | TypeScript 및 Vite 통과 |
| 새 Python 모듈·테스트 Ruff 검사 | 통과 |
| `git diff --check` | 통과 |

집중 E2E는 구매 미리보기→저장→40만 원 합산 납부→잔여 80만 원→15만 원 부분 환불→잔여 65만 원, 연결 거래 삭제 차단, 409 후 배분 입력 보존, 모바일 페이지 가로 넘침 및 44px 버튼, 응답 유실/잘못된 응답 후 새로고침·동일 요청 재시도를 확인했다. 데스크톱·모바일 캡처도 확인했다.

백엔드 할부 테스트 45개는 정수 나머지·말일·윤년, 실제 소비 중복 방지, 부분 배분·합산 한도와 롤백, 환불, 원자적 구매 저장, 같은 UUID 재시도, 동시 저장의 재사용/충돌, 연결된 거래의 수정·삭제 차단, 계정 검증, 예정일 조정, 미확인 회차 경고, 반복 카드값의 합산 충당 능력, 활성/보관 시나리오와 과거 기준일의 납부 경계, 일회성 추정 제외 선택, v6→v8 및 v7→v8 마이그레이션 보존·멱등성을 검증한다.

전체 테스트에서 발견한 테스트 자체의 문제도 정리했다. 새 E2E는 만든 일정·배분·거래를 정리해 기존 온보딩 테스트에 영향을 주지 않는다. 기존 규칙 편집 테스트는 URL 변경 직후의 수동 unload 이벤트 검사 대신 React 정리 완료까지 polling한다. 기존 현금 설정 테스트는 revision 컬럼을 마지막 위치가 아닌 이름으로 비교한다. 개시잔액 저장 중 잠금 테스트는 250ms 고정 지연 대신 두 상태 검사가 끝날 때까지 요청을 보류해 타이밍 의존성을 제거했다.

최종 ship 리뷰에서 응답 지연으로 저장이 계속 잠기는 문제와 과거 기준일 이후 구매가 반복 청구액의 한도를 소비하는 문제를 수정했다. 미리보기·저장은 15초 후 입력 잠금을 해제하며 저장 결과가 불명확하면 sessionStorage의 동일 요청으로만 확인한다. 미리보기 후 입력을 바꿔도 구매 폼을 열린 상태로 유지한다. 할부 집중 E2E는 일정 변경→납부 연결→배분 해제→일정 삭제 후 원장 보존도 확인했다.

이미 연결한 자동 납부 거래가 있어도 반복규칙을 삭제할 수 있도록 v8에서 `source_rule_id`만 해제하는 정리를 허용한다. 거래 금액·분개·배분·편집 메타데이터의 변경은 계속 차단한다. v7 원본 마이그레이션을 유지하고 별도 v8 보완을 등록해 기존 개발 DB에도 적용되도록 했으며, 검증에는 임시 DB만 사용했다.

범위 감사는 승인된 계약 22/22 항목 완료다. 테스트 커버리지 93%는 30개 경로군 표본의 정성 평가이며 계측된 행·분기 커버리지가 아니다. 조회·브라우저 저장소 오류 복구 및 중복 선택 UI 자동화는 표본의 잔여 검증 범위다. 중복 판단의 백엔드 검증은 포함한다.

## 전망 성능

같은 머신에서 변경 전 HEAD와 변경 후를 각각 5회 준비·30회 측정했다. 기존 fixture는 계정 250개, 실제 거래 50,000개, 실제 규칙 200개, 시나리오 규칙 100개, 예정 거래 500개다. 할부가 없는 기존 사용 경로의 회귀를 검증하며 대량 할부 전용 부하 시험은 아니다.

| 지표 | 변경 전 | 변경 후 | 기준 |
|---|---:|---:|---|
| 서비스 SQL | 9 | 10 | 18 이하 |
| API SQL | 9 | 10 | 18 이하 |
| 서비스 p95 | 166.7ms | 186.1ms | 증가 25% 이하: 통과 |
| API p95 | 169.4ms | 185.1ms | 증가 25% 이하: 통과 |

## 범위와 운영

- 원화 무이자 새 구매만 지원한다. 유이자는 원금과 별도 비용 구성요소로 확장하도록 [TODO](../../TODOS.md)에 기록했다. 진행 중 할부 중도 등록과 명세서 자동 수집은 제공하지 않는다.
- 현재 스키마 v8은 기존 자동 백업·순차 마이그레이션 경로로 적용된다. v7에서 이미 기록한 할부 납부 배분을 보존하면서 카드 납부 반복 규칙의 삭제를 허용한다. 개발 검증은 임시 DB로 실행했다. 구버전 앱으로 돌아가려면 대응하는 마이그레이션 전 백업이 필요하다.
- 빌드에는 번들 500KB 초과 경고, 백엔드에는 기존 Starlette/httpx 사용 중단 예고가 출력됐으며 실패는 아니다.
- 실행 검증 결과는 이 작업의 도구 출력에서 확인했다. 임시 로그·스크린샷·벤치마크 파일의 장기 보존은 보장하지 않는다.
