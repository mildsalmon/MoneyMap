# 대시보드 잔액 그룹화 검증

대상: `feature/dashboard-balance-groups`, 기준 main `d3be5aa`.

## 코드 리뷰

gstack 엔지니어링 계획 검토와 코드 리뷰를 수행했다. 독립 에이전트가 테스트, 유지보수성·단순화, 디자인·성능, adversarial 관점으로 검토했다. 모두 같은 모델 계열이며 교차 모델 검증으로 간주하지 않는다. Codex 호스트의 중첩 Codex 실행은 생략했다.

- 일반 계정이 부모가 된 기존 데이터의 테스트를 보강했다. 부모 직접 잔액 50원, 중간 그룹 직접 잔액 25원, 하위 잔액 3,000원의 자산 소계는 3,075원이다.
- 그룹 제목 간격을 디자인의 4px 단위에 맞춰 12px로 조정했다.
- API가 직접 잔액을 반환함을 확인했다. 계정 트리의 유형·부모·보관 불변식과 조회 훅의 상태 초기화를 함께 검토했다.
- 최종 코드에 남은 확인된 결함 없음.

## 자동 검증

- Backend: 480 passed (21.09s).
- Frontend build: 통과. 기존 500kB 번들 경고는 유지된다.
- Frontend E2E: 173 passed (2.7m).

v0.8.5.0 릴리스 준비 중 같은 제품 코드(`2a4ba43`)로 전체 검증을 다시 실행했다. Backend 480 passed (18.22s), frontend E2E 173 passed (2.6m), production build 통과. 아래 브라우저 QA는 동일 코드에 대한 앞선 실행 결과이며 재실행으로 표시하지 않는다.

첫 전체 실행에서 170개가 통과하고 3개가 실패했다. 두 테스트의 예전 표 DOM 구조 선택자와 빈 신용카드 그룹을 표시한다는 기존 기대값을 새 명세에 맞췄다. 기존 두 열/한 열 레이아웃, 상환 후 자산 분류 검증을 유지한다.

잔액 전용 E2E는 자산·부채 분리, 저장 순서, 중첩 동명 경로, 부모 직접 잔액, 소계 중복 방지, 보관·복원, 마이너스통장 상환, 0원, 빈 그룹, 계정/잔액 로딩·오류·재시도, 375px 긴 이름을 다룬다.

## 브라우저 QA

gstack browse로 별도 임시 DB의 실제 API와 React UI를 사용했다. 변경 범위인 대시보드와 계정 보관·복원 연계를 확인했다.

- 1440×1100: 자산/부채 별도 표, 그룹 제목·경로·소계, 중립적인 부채 배지와 음수 부호 확인.
- 375×812: 이름 줄바꿈, 금액 정렬, 세로 배치 확인. document scrollWidth = 375로 가로 넘침 없음.
- 자산 소계 4,700,000원, 마이너스통장 부채 소계 -250,000원, 카드 -480,000원, 전체 순자산 3,970,000원 확인.
- 계정 화면에서 마이너스통장을 보관하면 해당 행과 빈 부채 그룹 소계가 사라지고 전체 순자산은 유지된다. 복원하면 다시 나타난다.
- 6개월 전망으로 전환해도 잔액 표가 유지된다. 페이지 이동 및 조작 후 콘솔 오류 없음.
- 스크린샷: 로컬 `/tmp/moneymap-balance-desktop.png`, `/tmp/moneymap-balance-mobile.png`.
