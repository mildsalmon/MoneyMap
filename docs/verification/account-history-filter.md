# 계정별 거래내역 검증

2026-11-14 · `feature/account-history-filter` · [설계](../designs/account-history-filter.md).

## 검증 범위

- 기존 거래내역 백엔드 집중 30개 통과: 그룹 직접 기록·다단계·보관 후손·태그 교집합·페이지·중복 분개를 확인했다. 일치 거래의 모든 분개를 유지하고 쓰기 없이 4회 조회(HTTP의 계정 존재 확인은 추가 1회)한다. 잘못된 계정/중복 조건은 422, 없는 계정은 404다.
- 새 E2E 5개와 기존 조회 상태 9개 통과: 계정 초안은 조회 전 요청하지 않고 프리셋·URL·Back·해제·재시도·늦은 응답·오류를 검증한다. 계정관리·대시보드·통계·흐름 링크의 기간/하위 범위와 보관 계정도 확인했다.
- 실제 API로 101개 거래를 생성해 그룹 클릭→두 번째 페이지→메모 수정·필터/포커스 복귀→다른 계정으로 변경→필터 제외 안내와 1페이지 보정을 확인했다. 임시 DB만 사용하고 테스트 거래는 정리했다.
- 390px 모바일에서 가로 넘침·계정 선택 44px·axe를 확인했다. 계정명을 실제 링크로 제공하므로 키보드와 새 탭 열기도 기존 브라우저 동작을 사용한다.
- 백엔드와 프런트/적대적 관점은 같은 모델의 독립 문맥에서 검토했다. 남은 구체적 결함은 없으며 외부 모델 리뷰는 하지 않았다.

## 범위·제한

현재 계층 기준이며 보관 계정과 과거 그룹 직접 기록을 조회한다. 실제 장부의 기존 전체 통화 범위를 유지하므로 원화 전용 통계·활성 계정만 표시하는 잔액 소계와 합계가 반드시 같지는 않다. 잔액 링크는 누적 기록, 수입·지출 링크는 원래 기간을 사용한다. 원장·계정·스키마를 수정하지 않는다. PR #18 위에서 분기한 로컬 기능으로 ship·main 병합은 별도 요청 단계다.
