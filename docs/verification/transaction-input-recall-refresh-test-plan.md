## Affected Pages/Routes
- /transactions/new: 반복 자동 채움, 저장 대기, 실패 복구, 실행취소.
- /transactions/:id/edit: 추천 요청 없이 기존 수정 기능 유지.
- 화면 이동 후 /transactions/new 재진입: 이전 저장 알림의 실행취소 보호.

## Key Interactions to Verify
- 서로 다른 추천의 아이템 A→B→C: auto/retained 계정은 변경, 직접 선택한 쪽은 유지. 같은 값 재선택도 직접 선택으로 보호.
- 저장 후 다음 거래: 계정 재적용, 날짜·금액·메모·태그를 추천이 바꾸지 않음.
- 저장 버튼 두 개와 Enter/폼 submit이 동일한 조건 적용. 추천 대기 중 자동 갱신 대상이 있으면 POST 없음. 양쪽 직접 선택이면 유효한 입력 저장 허용.
- 조회 실패/5초 시간 초과: 계정 값·출처·입력 보존, 유효하면 저장 가능, 안내와 명시적 재조회. 재조회 자체는 거래 POST 없음.
- 실행취소 성공: 현재 계정과 출처 유지, 대기 잠금 없음. 아이템 변경/최근 아이템 선택/명시적 재조회 후에는 새 추천 적용.

## Edge Cases
- 요청 시작 5초 전후를 제어 시계로 검증. 200ms debounce 중 저장도 차단.
- A→B→A, 응답 역전, 시간 초과 후 늦은 응답, 재조회 중 이전 응답, IME, 분할 전환, 화면 이탈.
- 없음/사용 불가/보관 계정/503/네트워크 실패. 한쪽 수동 선택과 추천이 같은 계정이면 검산으로 저장 차단.
- 이관 기록의 명시적 확인 및 수동 선택 보호.
- 저장 중 새 초안, 중복 제출, 저장 실패에서 입력 보존 및 쓰기 자동 재시도 없음.
- 저장→다른 화면→재진입→이전 알림 실행취소. DELETE 진행 중 이동 후 늦은 완료. 현재 선택 보존 및 이후 명시적 재조회 복구.
- 실패한 실행취소는 실패 안내 유지. 수정 화면은 추천 호출 0회와 거래/분개 ID 보존.

## Critical Paths
- 두 계정 조합의 실제 저장 이력을 격리 DB에 준비, 아이템별 자동 채움→저장→다음 아이템→실행취소→재조회.
- 느린 조회 중 제출 시도 POST 0회, 종료 후 유효한 제출 정확히 1회.
- 화면 재진입에도 실행취소가 작성 중인 계정을 변경하지 않음.

## Execution
- 실제 사용자 DB와 8765/5173 개발서버를 사용하지 않는다. 격리 DB와 별도 포트 사용.
- backend: cd backend && uv run pytest
- frontend: cd frontend && npm run e2e (격리 포트 환경변수 설정)
- frontend build: cd frontend && npm run build
- 브라우저 QA는 위 흐름을 별도로 확인하며 테스트 계획 작성만으로 통과를 기록하지 않는다.
