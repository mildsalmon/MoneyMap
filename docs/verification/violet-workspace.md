## 범위와 검토

- gstack design-consultation으로 사용자 제공 이미지의 색·카드·간격을 디자인 기준으로 정했다. 에이전트 3명이 방향/독립 화면 검토, 공통 셸, 대시보드 구현을 나눴고 구현 담당자끼리 서로의 변경을 읽기 전용으로 교차 검토했다.
- 보라색 메뉴·라벤더 작업 공간·흰 카드와 실제 데이터로 동작하는 바로가기를 구현했다. 순수입은 기존 월 수입에서 월 지출을 뺀 값이다. 반복 규칙 수는 기존 조회 결과를 사용한다.
- 기존 계정 잔액·지출의 전체 행, 계정 필터 링크, 거래 방향 색과 거래 후 잔고, 수정 복귀 위치, 검산 상태, 차트 계단 곡선·키보드 탐색·표 전환을 유지한다. 백엔드·스키마·장부 쓰기 경로는 수정하지 않았다.
- 독립 화면 검토에서 모바일 SVG 축 글자가 과도하게 축소되는 문제를 발견해 차트만 자체 수평 스크롤하도록 수정했다. 전체 회귀 검증에서 발견한 1100px 하단 표 배치 문제는 기존 1200px 미만 한 열 배치 계약을 복구해 해결했다. 기존 assertion을 완화하지 않았다.

## 추가 검증

`frontend/e2e/violet-dashboard.spec.ts`의 4개 테스트는 1440/1024/720/390px에서 다음을 확인한다.

- 4개 지표와 계정 잔액의 실제 렌더링, 메뉴 8개와 활성 표시, 페이지 전체 가로 넘침 없음.
- 메뉴 최소 높이 44px와 axe WCAG 2 A/AA·2.1 AA 검사 위반 없음.
- 모바일의 읽을 수 있는 차트 너비·스크롤 안내·즉시 보이는 표 전환 버튼.
- 반복 규칙 관리·새 거래 기록·거래 모두 보기의 실제 화면 이동.

화면 캡처는 합성 데이터와 고정 날짜를 사용한다. 실제 사용자 DB를 읽거나 쓰지 않았다. 1440/390px 실제 앱 캡처와 HTML 프리뷰는 로컬 `~/.gstack/projects/MoneyMap/designs/violet-workspace-20261115/`에 보관한다.
