## 구현

- 자동 선택·저장 후 유지된 계정은 새 아이템의 추천으로 갱신하고, 직접 선택한 계정은 차변·대변 각각 보호한다.
- 추천 대기 중 저장 버튼과 submit 처리에 같은 판단을 적용한다. 양쪽 모두 직접 선택한 경우에는 유효한 거래를 저장할 수 있다.
- 실제 조회 요청에 5초 제한을 적용한다. 실패·시간 초과 시 계정 값을 보존하고 재조회 버튼을 제공한다.
- 실행취소 성공 시 기존 값을 보호한다. 화면 재진입과 늦게 도착한 응답에서도 보호하고, 아이템 변경이나 명시적 재조회로 해제한다.

## 코드 검토와 수동 QA

동일 호스트의 테스트·유지보수성·성능·디자인·단순화·red-team 및 별도 비판적 코드 검토에서 남은 코드 발견 사항은 없었다. 외부 Codex 검토는 실제 호스트 확인 결과 `under_codex`로 unavailable이며 중첩 외부 프로세스를 실행하지 않았다. 동일 호스트 검토를 외부 모델 검토 완료로 세지 않는다.

2026-09-21 `9523c2f`에서 격리 DB와 backend 8998/frontend 5408로 수동 QA를 완료했다. 신규 입력·거래 내역·거래 수정의 3개 경로와 스크린샷 7개를 확인했고 새 발견은 0건이었다. 연속 아이템, 공유 자동 계정 안내, 수동 한쪽 보호, 저장·실행취소·재진입, 5초 제한·503·키보드 재조회, 390×844 모바일, 수정 화면의 추천 미호출을 확인했다. 전체 앱 품질이나 모든 시간 순서 조합을 검증했다는 뜻은 아니다.

로컬 상세 증거는 ignored `.gstack/qa-reports/qa-report-recall-refresh-2026-09-21.md`와 같은 디렉터리의 스크린샷에 있다. 이 파일들은 저장소에 포함되지 않으며 이 문서가 공유 가능한 요약이다. 제품 소스는 이후 바뀌지 않았다. ship 시점에는 5408 QA 서버가 종료되어 새 live QA를 실행하지 않고 이 기록을 사용했다.

## 남은 검증 범위

AI가 평가한 검증 항목은 22/26(약 85%)이며 도구로 계측한 줄·분기 커버리지가 아니다. 전체 테스트 통과를 아래 계획 항목의 완전한 검증으로 표현하지 않는다.

- 실제 last-pair 네트워크 거절(`route.abort`) 사례: 현재 오류 테스트의 503은 HTTP 오류다.
- 수동 선택과 추천이 같은 계정이 되는 충돌의 브라우저 POST 0회 검증: 상태 함수의 검산 실패는 검증했다.
- 실행취소 이외의 전역 갱신 세대와 늦은 추천 응답의 집중 경쟁 검증.
- IME 조합 중 또는 분할 모드에서 실행취소가 완료되는 집중 검증.
- 재조회 버튼의 실제 44px 크기 assertion. CSS 최소 높이는 구현했고 모바일 화면은 QA했으나 크기를 직접 검증하는 assertion은 없다.
